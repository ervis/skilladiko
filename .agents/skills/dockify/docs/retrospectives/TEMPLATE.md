# Retrospective Template

Use this template for tasks that revealed meaningful lessons about planning, execution, prompting, workflow, or agent behavior.

Not every task needs a retrospective. Use one when the work exposed confusion, rework, weak planning, missed constraints, or useful process improvements.

## Summary

- **Task / change:**
- **Related issue / PR / design doc:**
- **Date:**
- **Author:**
- **Status:** draft / final

## Goal

- What was the task trying to achieve?
- What outcome was expected?

## Original Plan

- What was the initial implementation plan?
- What assumptions did the plan rely on?
- What parts of the plan were strong?
- What parts of the plan were weak or incomplete?

## What Actually Happened

- What implementation path was actually taken?
- What changed from the original plan?
- What unexpected constraints, facts, or behaviors were discovered?

## Iterations and Back-and-Forth

- What back-and-forth was needed to reach the correct implementation?
- What decisions had to be revisited?
- Where did the work stall, drift, or require clarification?

## Agent Performance

- What did the agent get right?
- What did the agent misunderstand or miss?
- What information would have helped the agent succeed faster?
- Did the agent follow the workflow and documentation expectations?

## Quality of the Plan

- Was the original plan good enough?
- If not, why not?
- What should be planned differently next time?
- What signals should have been noticed earlier?

## Quality of the Implementation

- What was done well?
- What created unnecessary complexity or rework?
- Were there avoidable mistakes?
- Were tests, docs, and invariants handled well?

## Lessons

- What should future tasks do the same way?
- What should future tasks do differently?
- What facts should be added to canonical docs?
- What process or prompt changes would reduce future mistakes?
